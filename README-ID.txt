AWAPART 66 v264 — kandidat produksi, BELUM diuji pada PostgreSQL atau Android build.
1. Ekstrak ZIP ke /opt/awapart66-v259/release-v264 melalui WinSCP.
2. Jalankan cd /opt/awapart66-v259/release-v264 && bash preflight.sh.
   Ini hanya membaca konfigurasi dan schema. Jangan jalankan migration.sql pada produksi dulu.
3. Uji migration.sql pada database salinan backup produksi, menggunakan psql -v ON_ERROR_STOP=1 -f migration.sql. Pastikan jumlah booking, metode bayar, admin dan unit sama sebelum/sesudah. Uji login dan semua API dengan konfigurasi terpisah. Migrasi mempertahankan tabel legacy, kolom commission_percent, tipe owner_id lama dan dukungan UNKNOWN; tidak menyalin data staging. Admin tunggal menjadi super_admin; konfirmasi otorisasi terlebih dahulu.
4. Sebelum cutover: hentikan penulisan data, buat backup baru DB, web, backend termasuk migrations, konfigurasi deployment dan direktori upload bukti pembayaran. Uji pemulihan. Gunakan deployment persisten (bukan hanya docker cp), PUBLIC_ORIGIN dan CORS produksi, email/OAuth produksi, dan cek Nginx. Jangan menimpa index atau web aktif sebelum uji lengkap. Rollback melalui image/source lama dan backup yang sudah diuji; jangan restore DB lama setelah transaksi baru tanpa rekonsiliasi.
5. Android: folder android berisi source dan workflow. Upload isi folder android ke root repo build, termasuk .github. versionCode 45 harus lebih tinggi daripada versi terakhir di Play Console; ubah bila perlu. Jalankan workflow release dengan signing secrets yang sudah ada. Jangan bagikan keystore/password. Hasil APK dan AAB baru tersedia setelah build berhasil. Uji APK pada perangkat, termasuk login, upload foto/bukti, booking dan navigasi. Periksa persyaratan Play Console, privasi, penghapusan akun dan target SDK sebelum submit. Akun developer harus dikelola orang dewasa yang memenuhi syarat.
